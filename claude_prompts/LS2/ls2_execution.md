# LS2 — Execution

Generated 2026-09-23 by planning prompt 4 of `ls2_prompts.md`, from the answers
to Q1–Q26.  That document holds the goal, the verified Context and the full Q&A;
this one holds the work.  Decisions are cited as **Q*n*** and refer to it.

## Goal

Bring LS2 into IOPtics as a benchmarked, non-fitting algorithm alongside BING,
run it as a ladder that separates its accuracy from the accuracy of its inputs,
then re-derive its empirical coefficients from L23.

**Exit criterion.**  A published report page that shows, on the same L23 corpus
RT-A used: LS2's `a`, `a_nw`, `bb` and `bb_p` against truth at three input rungs
and three inelastic variants; an explicit "not applicable" row where BING has
`a_ph`/`a_dg` and LS2 has nothing; and the same table again with coefficients
re-derived from L23 instead of from Hydrolight-plus-Petzold.

## Pinned decisions

Self-contained so no task needs to re-read the Q&A.

- **Shape (Q1, Q13).**  A second spec type `DirectSpec`; LS2 carries an honest
  `fit_method='direct'`; contests pool across `fit_method` via a new `pool`
  column so LS2 meets BING in **both** the χ² and MCMC contests, with the
  **headline quoted against MCMC** for continuity with RT-A (Q23).
- **Ladder (Q2).**  Three input rungs on L23: (i) true Kd + true b_p;
  (ii) true Kd + OC4v4 b_p; (iii) NN Kd + OC4v4 b_p.  Plus a fourth
  **diagnostic** rung (Q9): published LUT at an effective μw derived from L23's
  own geometry.
- **Inelastic (Q4).**  X = 1, 2 and 4; κ off for X=1, on for X=2 and 4.
- **Scoring (Q5).**  `frac_ok` for direct algorithms = all requested outputs
  finite and positive.  Fit-quality family emits **NaN, never 0.0**.  NaN
  reasons recorded **per wavelength** in `results_spectral` (Q24).  Head-to-head
  on `a`, `a_nw`, `bb`, `bb_p` only; `a_ph`/`a_dg` appear as explicit
  "not applicable" rows, unscored on PANGAEA (Q25a).  LS2 is never an exemplar
  and the ladder page says so (Q25b).
- **Re-derivation (Q6, Q11).**  Refit a and bb from L23 X=1 as **smooth
  low-order functions of μw** (3-node μw as the validation check) on a reduced,
  smoothed η axis; held-out split **by IOP scenario, never by row**.  The
  re-derived object need not be shape-compatible with the published
  (21, 8, 4)/(21, 8, 3) arrays.  Refit κ from the matched X=1 vs X=2 pair over
  **350–750 nm** with a bb/a range that covers L23 (Q12).
- **⟨Kd⟩₁ (Q10).**  Canonical definition is `ln[Ed(0⁻)/Ed(z₁)] / z₁`, computed
  from `Ed_z` alone; the other two (trapezoid of `KEd_z` over the stored
  `z1_lambda`; trapezoid over an Ed-derived z₁) are selectable options, and the
  700 nm discrepancy is reported once as a sensitivity.
- **Pure water (Q21).**  LS2 brings its **own** a_w/b_w from ocpy — it may not
  read L23's from the truth dict — and δ = (ours − L23's) is measured across
  400–750 nm and reported on the ladder page, because it biases `a_nw` directly.
- **Raman (Q14, Q22).**  The benchmark runs **iterated** to LS1's criterion
  (bb/a change < 0.1%, cap 10).  The authors' oracle is single-pass, so oracle
  tests pin `max_iter=1` and convergence is tested by self-consistency.  The
  single-pass-vs-iterated difference is reported once.  κ above 702 nm is
  **NaN** (counted as a NaN reason), never the silent clamp.
- **Noise (Q15).**  Same noise *form* as RT-A (the `pace` model), not the same
  draws; every rung sees it.  Kd noise is its own sensitivity rung, not baked
  into rungs (i)/(ii).
- **Kd networks (Q16, Q20, Q26).**  Build **two** L23-trained networks — a
  hyperspectral one (all channels 400–750 nm, the LS2-PACE deliverable, no in
  situ validation) and a five-band SeaWiFS-like sibling (443, 490, 510, 555,
  670) that can be checked against PANGAEA.  Clear-water scope only; no turbid
  branch.  Predict the **μw-normalised** ⟨Kd⟩₁ and multiply the analytic 1/μw
  factor back.  Follow `robust/rt/emulator.py`'s pattern (Flax/Optax,
  standardisation, explicit out-of-domain envelope).  Splits by IOP scenario.
- **Code layout (Q14).**  Fixes and new physics go **upstream into `ocpy`**;
  IOPtics gets a thin adapter, the `DirectSpec`, and the driver.
- **PACE application** is deferred — the `pace_pab_100` artifact is not on this
  machine and no local PACE product carries Kd or per-pixel sza.

### The authors' own distribution — found 2026-09-23, and it settles three things

`https://github.com/SIO-Ocean-Optics-Research-Laboratory/LS2_Distribution` and
`https://github.com/SIO-Ocean-Optics-Research-Laboratory/Kd_NN_Distribution`
(MIT licensed, by Kehrli, Taylor, Reynolds, Stramski and Loisel).  Clone both
before starting; they are the reference implementation the `ocpy` port came from.

1. **`bp_from_Chla.m` closes Q19.**  The relation is
   `b_p(660) = 0.347·Chl^0.766`, then `b_p(λ) = b_p(660)·(λ/660)^(−1)` — a plain
   **λ⁻¹**, *not* Morel & Maritorena's Chl-dependent exponent, even though the
   authors cite MM01 for it.  This is exactly why the reference vector's `b_p`
   column is an exact λ⁻¹ power law.  Nothing needs to be recalled or guessed.
   `loisel1998.pdf` is in JXP's Drive (`Oceanography/Papers`, file id
   `1y5jaZ2UgaklKBp7BhIdI1DNjpBK02XXQ`) if the 0.347 amplitude needs its
   primary source; no `morel2001` was found there.
2. **The stale-corner defect is ours.**  `LS2_main.m` recomputes **all four**
   `a` corners in the Raman branch.  The Python port's placeholder comment is a
   porting bug, not something inherited.
3. **The authors' code is single-pass by design** — its docstring says the
   output "is recalculated via a single iteration" — while the paper's Table 1
   step 9 says iterate to convergence.  Both facts belong in the report.

**And `Kd_NN_PACE.m` already exists.**  The authors have published a PACE Kd
network taking Rrs at **12 PACE wavelengths** (440, 470, 490, 510, 530, 560,
580, 600, 620, 640, 670, 700) with the switch on Rrs(490)/Rrs(560) ≥ 0.85.  This
was not known when Q3/Q16/Q17 were answered.  It does not replace the L23-trained
networks — those are ours, and the point is to train on our own RT — but it is
the natural **baseline** for them and the right Kd source for rung (iii) on
PACE-like data.  Task 3 ports it; **Q27 in the Q&A below asks whether it should
also become rung (iii)'s Kd on L23**, replacing the MODIS-band network.
